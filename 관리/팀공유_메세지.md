```
[본프로젝트 설계 정리 · 확인 부탁드립니다]

세현님 목업·기획안, 재정님 3모드 확장안·OCR DB 설계안 위에 제 파트를 얹어서

github.com/bobohyeon/deliver  (브랜치 docs/산출물-정리-0805)

■ 제품 정의가 한 발 나갔습니다

전에는 "문서를 올리면 프로젝트가 자동으로 정리되는 도구" 였는데,
"그 태스크 모음집으로 뭘 하는데?" 라는 질문에 답이 없었습니다.

  문서를 올리면 프로젝트 문서가 나오는 도구

회의록·계약서·보고서를 넣으면 할 일·결정·일정·금액을 뽑고,
그 조각을 모아 주간 보고서·결정사항 대장·회의 안건을 만듭니다.

이게 뜬금없는 게 아니라, 미니 프로젝트에서 우리가 손으로 만든 것들입니다.

  이슈 대장 46건
  결정사항 대장 29건 (미채택 대안·이유까지)
  주간 보고
  WBS 4시트

이걸 자동으로 만드는 게 제 파트(DLV 영역)입니다.
그리고 시연도 우리 팀 문서로 하면 됩니다 —
"우리가 손으로 만든 산출물을 이 도구가 자동으로 만듭니다" 로요.
손으로 만든 것과 자동 생성한 것을 나란히 놓을 수 있어서
미니 프로젝트에서 지적된 "주장에 기준이 없다" 를 피할 수 있습니다.

세 사람 역할이 입력 → 처리 → 출력으로 갈립니다.

  세현님   그릇을 만든다        프로젝트·권한·태스크
  재정님   입력을 믿게 만든다   문서 하나를 정확히 (OCR 검수)
  저       출력물을 만든다      조각을 모아 문서를 만든다


■ 전제 — 구현은 20일입니다

  설계·합의      8/10 ~ 8/14    5일
  구현           8/17 ~ 9/5     20일   (코드 프리즈 9/4 금)
  테스트·산출물   9/7  ~ 9/11    5일
  리허설·예비     9/12 ~ 9/13    2일

영업일 15일, 3인이면 45 인일입니다. P0+P1 이 80개라 다 못 합니다.
덜어내기보다 묶는 방식으로 갑니다 — 액션아이템·결정·일정·금액이
같은 골격(제안 카드 → 승인 → 태스크)을 쓰기 때문에
골격을 한 번 만들면 두 번째부터 훨씬 쌉니다.


■ 설계가 크게 단순해졌습니다 — 폐기한 것 5개

제가 전에 말씀드린 것 중 상당수를 뺐습니다. 세현님 지적이 계기였습니다.

1) 분석기 선택 규칙 (문서 유형별로 어떤 분석기를 돌릴지) — 폐기

   세현님이 "그렇게 가면 프롬프트가 병렬 처리가 안 된다" 고 하셨는데 맞았습니다.
   분류를 먼저 돌려야 해서 asyncio.gather 가 두 단계로 쪼개지고,
   요약이 분류를 기다릴 이유가 없는데 1.6초를 버리는 구조였습니다.

   그리고 더 근본적인 문제가 있었습니다.
   회의록이나 보고서에도 금액이 나옵니다. "예산 3천만원 추가 요청" 같은 거요.
   유형으로 금액 분석기를 껐다 켜면 오히려 놓칩니다.

   → 분석기 4개를 유형 구분 없이 항상 다 돌립니다. gather 한 번입니다.

     summary   요약        (기존 코드 그대로)
     category  분류        (7종 + reason)
     extract   액션·결정·일정  (신규)
     amount    금액        (신규)

   analyzer_rules 테이블도 안 만듭니다.
   그리고 이건 FastAPI 라우터와 무관한 얘기였습니다.
   analysis_router 는 analyzer_types 를 그냥 넘기기만 해서 안 고칩니다.

2) 근거 페이지·좌표 표시 — 폐기

   목업 카드에 "근거 · 3페이지" 가 있었는데,
   지금 분석기 규격이 analyze(text: str) 로 텍스트만 받아서 페이지를 모릅니다.
   표시하려면 규격을 바꿔야 하고, 그러면 분석기 규격(저) →
   텍스트 조립 offset(재정님) → 하이라이트 UI(세현님) 세 사람이
   합의하고 서로 기다려야 했습니다.

   → "왜 그렇게 판단했는지"(reason) 만 한 줄 표시합니다.
     분류 분석기가 이미 쓰는 방식이라 새 구조가 아닙니다.
     20일에 세 사람의 대기 하나를 없앤 셈입니다.

3) 금액 추계 · 단가 마스터 — 폐기

   제가 계속 "최대 위험" 이라고 했던 부분입니다.
   없는 금액을 단가 x 수량으로 만들어내려니 단가 근거를 댈 수 없었습니다.

   → 있는 금액을 모으는 것(집계)으로 좁혔습니다.
     unit_prices, cost_estimates, cost_estimate_lines 세 테이블이 사라졌고
     "그 숫자 근거가 뭐냐" 에 전부 문서에서 나왔다고 답할 수 있습니다.

   집계가 뭘 하냐면 이런 겁니다.

     용역계약서_최종.pdf       계약금액   72,000,000
     계약_변경합의서_스캔.jpg   증액       +15,000,000
     3월 2주차 주간보고.docx    집행액      60,000,000
                        ↓
     현재 계약금액 87,000,000 · 집행 60,000,000 (69%) · 잔액 27,000,000
     ⚠ 변경합의서 기재 총액(85,000,000)과 계산값 불일치 → 확인 태스크

   문서 하나로는 알 수 없습니다. 세 문서를 열어서 손으로 계산해야 하는 일입니다.
   그리고 재계산으로 대조되니까 검증 가능한 유일한 기능입니다.

4) 비용추계서 서식 출력 — 폐기 (타깃 사용자와 안 맞습니다)

5) 원문 위치 하이라이트 — 폐기 (2번과 같은 이유)


■ 두 분 것 위에 제가 얹는 것

새 화면은 사이드바에 "산출물" 메뉴 하나뿐입니다.

[세현님 목업 위에]

  문서 상세 우측 패널에 금액 항목 섹션
    액션아이템 카드와 똑같은 형식입니다. 제안 카드·승인/수정/거부·확신도·
    출처 링크 전부 그대로 씁니다. UI 패턴을 새로 안 만들어서 프론트 작업이 적습니다.

  합계 대조
    항목 합계와 문서 기재 합계를 맞춰봅니다. 금액이 다른 분석기보다 센 지점입니다.
    액션아이템은 맞는지 알 방법이 없는데 금액은 재계산으로 대조됩니다.

  태스크 자동 제안
    합계가 안 맞으면 태스크 제안이 생깁니다. 자동 등록은 안 합니다.
    검증만 하는 기능이면 문서가 깨끗할 때 보드가 비는데,
    금액 불일치는 실제로 자주 있어서 승인 UI·태스크가 다 동작하는 화면이 됩니다.

  프로젝트 금액 현황
    프로젝트 카드와 대시보드에 미확정 금액 지표를 넣습니다.

[재정님 파이프라인 위에]

  검수된 텍스트를 분석 입력으로
    어느 revision 을 썼는지 기록해서 검수 전후 금액 오류 건수를 비교할 수 있게
    하려고 합니다. 재정님 검수 모드의 효과를 수치로 보여줄 수 있습니다.

  revision 사슬을 금액·결정·일정까지 연장
    analyses.source_text_revision 두신 걸 그대로 이었습니다.
    OCR 을 고치면 이미 뽑아둔 것들이 자동으로 "오래됨" 이 됩니다.

  일괄 업로드에 배치 유형 지정
    100건을 각 파일마다 고를 수 없으니 배치 단위로 한 번 지정합니다.
    기본값은 자동 판별입니다.

제 파트 원칙은 하나입니다.
"LLM 은 문서에 있는 것만 뽑고, 계산과 집계는 코드가 한다."


■ DB 변경 — 세현님 쪽만 있습니다

재정님 파트는 변경이 없습니다. 설계안 그대로 채택했습니다.

세현님 필수 3개

  tasks.completed_at (+ updated_at)
    주간 보고서에 "이번 주 완료 태스크" 를 넣어야 하는데 완료 시각 컬럼이 없습니다.
    status 가 DONE 인 건 알아도 언제 DONE 이 됐는지 모릅니다.
    목업 보드가 이미 "3월 7일 완료" 를 표시하고 있어서 담을 곳이 필요합니다.

  tasks.source_amount_item_id
    태스크 출처가 2갈래(액션아이템 / 금액 항목)가 됩니다.
    nullable FK 2개 + CHECK 로 둘 중 하나만 채워지게요.
    source_type + source_id 방식은 FK 를 못 걸어서 안 쓰는 게 좋다고 봅니다.

  documents.document_type 7종 enum
    지금 항상 general 인데 실제 값이 들어갑니다.
    계약서 / 계약변경 / 회의록 / 보고서 / 공지사항 / 메뉴얼 / 기타
    계약변경을 나눈 건 원계약은 계약금액, 변경합의서는 증감액을 뽑아서
    프롬프트 힌트가 달라야 하기 때문입니다.
    분석기를 껐다 켜는 용도가 아니고 목록 필터·프롬프트 힌트·산출물 분류에 씁니다.

선택 3개

  documents.document_type_source (USER / AI / USER_CORRECTED)
    사람이 AI 판별을 고친 비율이 곧 분류 오류율입니다.
    기획안 지표 "분류 정확도 85%" 를 별도 정답 데이터 없이 잴 수 있습니다.

  projects.started_on / due_on   일정 산출물용
  activity_logs.action_type 값 목록   같이 정하면 좋겠습니다
```
