## 3. 계획과 실제의 어긋남 — 세 가지

### 3-1. 담당 배정이 문서 3곳에서 다르다

| 출처 | 세현 | 재정 | 보현 |
|---|---|---|---|
| WBS 인일배분 시트 | **기반·인증·프로젝트·태스크** | 업로드·OCR 검수·일괄 | 분석기 4개·금액·산출물·문서 조회 |
| **기능명세서** | **분석 `ANL`** | `AUTH`·`PRJ`·`DOC`·`REV`·`BAT` | `AMT`·`VIS`·`DLV`·`RAG` |
| 팀공유 메시지 | 그릇 (프로젝트·권한·태스크) | 입력 품질 (OCR 검수) | 출력물 (산출물) |

**WBS 는 세현=인증, 기능명세서는 세현=분석으로 정반대다.**

**실제 코드는 기능명세서 쪽과 맞는다** — 인증·프로젝트를 재정님이 하셨다.
따라서 **WBS 담당 열이 낡았다.** `산출물_변경대기_목록.md` B-1 이 이걸
"담당 재편 확정 대기" 로 남겨둔 상태다.

**8/14 킥오프(`1.3.3`)에서 정해야 한다.**

### 3-2. 세현님이 P3 작업을 먼저 하셨다

이건 비난이 아니라 **명세서가 현실을 못 담고 있다는 신호다.**

| 세현님 담당 · 명세서 기준 | 작업명 | 우선 | 상태 |
|---|---|---|---|
| `ANL-01` | 요약 분석기 | P0 | 기존 코드 그대로 (수정 안 함이 맞다) |
| `ANL-02` | **분류 분석기** (9종 + `reason`) | **P0** | **후보가 6종이다 — 안 맞는다** |
| `ANL-07` | 분석 이력 보존 | P0 | 기존 |
| `ANL-08` | 프롬프트 버전 관리 | P0 | 기존 (`PROMPT_VERSION="v1"`) |
| `ANL-03` | **항목 추출 분석기** (액션·결정·일정 한 번에) | **P1** | **미착수** |
| `ANL-14` | 결정사항 추출 | P1 | **미착수** |
| `ANL-15` | 일정·기한 추출 | P1 | **미착수** |
| `ANL-05` | 분석 진행률 일반화 | P1 | **미착수** |
| `ANL-06` | 확정 텍스트 기준 분석 (검수 반영) | P1 | **미착수** |
| `AMT-01` | 금액 항목 추출 | P1 | **미착수** |
| `AMT-09` | 금액 판단 근거 표시 | P1 | **미착수** |
| `SYS-09` | 에러 로그 누락 수정 (`ISS-001`) | P0 | **조치 예정 (8/17)** |
| `SYS-10` | 로컬 sLLM 옵션 | **P3** | **완료** |

**LLM 모델 선정 자체는 필요한 일인데 명세서에 그 항목이 없다.**
`SYS-10`(P3)으로 잡히니 P3 를 먼저 한 것처럼 보인다.
**모델 비교·측정을 정식 작업으로 올려야 한다** — 나는 임베딩 쪽에서
같은 문제를 겪어 `RAG` 영역 12건을 신설했다.

### 3-3. 분류 분석기 후보가 문서 유형과 안 맞는다

**코드로 확인한 사실이다.**

| | 값 |
|---|---|
| `analyzers/prompts.py` 의 `CATEGORY_CANDIDATES` | **6종** — 계약서 · 보고서 · 회의록 · 공지사항 · 메뉴얼 · 기타 |
| `models/enums.py` 의 문서 유형 (보현 작업) | **9종** |
| 기능명세서 `ANL-02` 판정 기준 | "7종 중 하나로 분류" |

**셋이 다 다르다.** 분류 결과가 `documents.document_type` 에 들어가는데
분류기가 낼 수 없는 값이 Enum 에 있고, 반대로 분류기가 내는 값이 Enum 에
없을 수 있다. **`ANL-02` 착수 전에 맞춰야 한다.**

## 6. 세현님 LLM 모델 시험에 대해 — 제안

**모델 시험은 필요한 일인데 명세서에 항목이 없다.** 그래서 `SYS-10`(P3)만
남고, 시험 자체는 기록되는 곳이 없다.

**임베딩 쪽에서 내가 겪은 것과 같은 문제였다.** 나는 `RAG` 영역 12건을
신설해서 해결했다. LLM 쪽도 같이 하면 좋겠다.

### 제안 1 — 측정 항목을 명세서에 올린다

| 기능 | 작업명 | 이미 있나 |
|---|---|---|
| `ANL-16` | 구조화 출력 검증·재시도 | **있다** (P1 · 보현 담당) |
| `ANL-17` | **평가셋 기반 정확도 측정 자동화** | **있다** (P1 · 보현 담당) |

`ANL-17` 판정 기준에 이렇게 적혀 있다 —
**"모델·프롬프트를 바꿔도 같은 자로 잰다. 세현님 모델 비교에 직접 쓰인다."**

**즉 측정 도구는 내 담당이고 판단은 세현님이다.** 아직 만들지 않았다.
`도구/embed-test` 와 같은 구조로 만들 수 있다.

### 제안 2 — 임베딩 시험에서 배운 것을 공유한다

| 배운 것 | LLM 시험에도 적용되나 |
|---|---|
| **질의를 일부러 다른 말로 쓴다** | 그렇다. 원문 단어를 그대로 쓰면 쉬운 문제가 된다 |
| **정답을 손으로 찍으면 라벨 검사 도구가 필요하다** | 그렇다. 내가 `check_queries.py` 로 라벨 오류 1건을 잡았다 |
| **표본이 작으면 1~2건 차이는 노이즈다** | 그렇다. 나는 34문항에서 1문항 차이로 모델을 확정하지 않았다 |
| **지표를 하나만 보면 순위가 뒤집힌다** | 그렇다. 내 경우 `R@1` 과 `R@5` 의 1위가 달랐다 |
| **무료 API 등급은 데이터를 학습에 쓸 수 있다** | **그렇다.** Gemini 무료 등급이 그렇다 (결과서 13.9절) |

**마지막 항목이 특히 중요하다.** 세현님이 LLM 을 API 로 시험하고 있다면
무료 등급에서 우리 문서가 나갈 수 있다. 로컬 Ollama 를 쓰고 있으면 해당 없다.

### 제안 3 — 파인튜닝 방침을 문서와 맞춘다

`관리/요구사항정의서.md` `COR-05` 를 이렇게 고쳐 놨다.

> 학습은 **출력 형식 안정화에만** 쓴다. 지식은 학습시키지 않는다.
> 학습 여부는 **측정 결과로 판단한다.**

**두 레포에 파인튜닝 스크립트나 학습 데이터셋이 없다.** 진행 중이면
어디에 있는지 알아야 하고, 안 하기로 했으면 문서를 또 고쳐야 한다.
