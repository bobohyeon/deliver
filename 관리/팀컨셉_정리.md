# DocFlow — 팀 컨셉 한 장 정리

발표 첫 장과 회의 첫 5분에 쓰는 문서다. 길게 쓰지 않는다.

---

## 한 줄 정의

> **문서를 올리면 프로젝트가 자동으로 정리되는 협업 도구.**

문서를 읽어 **할 일 · 금액 · 결정사항**을 뽑아내고, 뽑아낸 모든 것에
**출처 문서와 판단 근거가 붙는다.**

---

## 문제

| | |
|---|---|
| 문서는 낱개로 존재하지 않는다 | 계약서 → 킥오프 회의록 → 주간 보고서 → 변경합의서가 **한 프로젝트의 맥락** 안에 있다 |
| 기존 PM 도구는 사람이 입력한다 | 회의록에 적힌 "다음 주까지 김 대리가 API 명세 확정"은 **누군가 손으로 티켓을 만들어야** 관리된다 |
| 뽑아낸 정보의 출처를 잃는다 | 2주 뒤 "그 얘기 어디서 나왔지?" 에 답할 수 없다 |

---

## 우리가 하는 이유

미니 프로젝트에서 **문서를 읽는 파이프라인을 이미 완성했다.** 새로 시작하지 않는다.

| 이미 있는 것 | |
|---|---|
| 추출 | PDF · DOCX · HWPX · 이미지, OCR 3종, 전처리 · 레이아웃 · 읽기순서 · 표 검출 |
| 분석 | 요약 · 분류, 프롬프트 버전 관리 |
| 구조 | 추출기 · 분석기가 **규격이 같아 갈아 끼울 수 있다** |
| 기록 | 토큰 · 지연시간 · 모델명을 남긴다 |

본프로젝트는 여기에 **프로젝트라는 맥락**과 **사람의 확정 절차**를 얹는다.

---

## 원칙 세 개 — 이것만 지킨다

### ① 문서가 원천이다

사람이 입력하지 않는다. 태스크도 금액도 **문서에서 나온다.**
사람이 원가를 입력하는 관리 모듈은 만들지 않는다.

### ② AI 는 제안하고, 사람이 확정한다

**자동 등록 금지.** AI 가 뽑은 것은 전부 승인 대기 카드로 뜨고,
사람이 승인해야 태스크가 된다. 확신도를 함께 보여줘 판단을 돕는다.

### ③ 근거 없는 결과는 만들지 않는다

AI 가 뽑은 모든 결과에 **어느 문서에서 나왔는지**와 **왜 그렇게 판단했는지**를
함께 보여준다. 판단 근거를 못 대는 결과는 제안하지 않는다.

> 원문 위치(페이지·좌표) 하이라이트는 범위에서 뺐다. 판단 근거 서술이 승인
> 여부를 정하는 데 더 직접적이고, 위치 추적은 분석기 규격을 바꿔야 해서 비용이
> 크다. 금액은 **합계 대조**로 따로 검증한다.

---

## 세 사람이 만드는 것

```
        문서 ──▶ 추출·OCR ──▶ 검수 ──▶ 분석기 ──▶ 제안 ──▶ 승인 ──▶ 태스크
                    │           │         │                          │
                  재정          재정      보현                      세현
                                                                (프로젝트·권한)
```

| 담당 | 만드는 것 | 한 문장 |
|---|---|---|
| **박세현** | 인증 · 프로젝트 · 멤버 권한 · 공통 인프라 | **맥락을 만든다.** 문서가 어느 프로젝트에 속하는지 |
| **최재정** | 처리 모드 3종 · OCR 검수 · 일괄 처리 | **입력을 믿을 수 있게 만든다.** 사람이 OCR 을 고친다 |
| **김보현** | 분석기 라우팅 · 금액 분석기 · 비용 추계 | **읽은 것으로 판단을 만든다.** 문서 유형별로 무엇을 뽑을지 |

세 파트가 **한 흐름에서 만난다.** 스캔 계약 변경합의서를 올리면 —
OCR 신뢰도가 낮아 경고가 뜨고(재정) → 사람이 금액 숫자를 고치고(재정) →
금액 분석기가 증감액을 뽑아 원 계약과 대조하고(보현) → 불일치 태스크가
프로젝트 보드에 뜬다(세현).

---

## 미니 프로젝트와의 차이 한 줄

| | |
|---|---|
| 미니 프로젝트 | 문서를 **읽었다** |
| 본프로젝트 | 읽은 것으로 **판단을 만든다** |

---

## 발표에서 이 순서로 말한다

1. 문서는 프로젝트라는 맥락 안에 있다 — 낱개 처리기로는 부족하다
2. 그런데 기존 도구는 사람이 입력한다
3. 우리는 문서에서 뽑는다. 단 **AI 는 제안만 하고 사람이 확정한다**
4. 뽑은 것에는 **출처 문서와 판단 근거가 붙는다**
5. 이게 가능한 건 미니 프로젝트에서 **읽는 부분을 이미 만들어 뒀기** 때문이다

**용어는 먼저 정의한다.** 미니 프로젝트 발표에서 "추출기 · 분석기가 무슨 뜻이냐" 를
질문받았다.

> 추출기는 **파일에서 글자를 꺼내는 부품**, 분석기는 **꺼낸 글자로 결과를 만드는
> 부품**입니다. 둘 다 규격이 같아서 갈아 끼울 수 있습니다.
