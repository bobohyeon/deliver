## 2. 세부내역

- 프로젝트 개발 계획 수립 (WBS·간트, 마일스톤 10개)
- 개발 환경 구축 (Docker Compose, Git 브랜치 전략, 코드 규약)
- 팀 역할 분담 및 인터페이스 사전 합의

- 외래키 인덱스 및 조회 성능 검증

### ■ 시스템 인터페이스 및 아키텍처

- 문서 업로드·조회·검수·챗봇 화면 UI 설계 및 구현
- 모듈 간 인터페이스 및 전체 아키텍처 설계
- API 계약서 작성 (엔드포인트 50개, 요청·응답 스키마)
- 오류 응답 규격 통일 및 오류 코드 체계 구축 (51종)
- 요청 추적 식별자 부여 및 로그 연계
- 사용자 인증 및 프로젝트 단위 접근 권한 설계 (권한 3종)
- 프로젝트 경계를 넘는 데이터 접근 차단 (데이터 접근 계층에서 강제)
- 비동기 작업 처리 구조 설계 (작업 큐, 진행 상태 표시)

### ■ OCR 및 로컬 LLM(Ollama/Gemma) 기반 문서 요약·자동분류 시스템 개발

- 문서 파일 업로드 및 전처리 (PDF·DOCX·HWPX·JPG·PNG)
- 다중 파일 일괄 업로드 및 파일별 성공·실패 표시
- 일괄 작업 대기열 관리 및 실패분 재시도
- 형식별 텍스트 추출 방식 판정 (텍스트 레이어 / OCR)
- OCR 기반 문서 텍스트 추출 (PaddleOCR)
- 페이지 이미지 생성 및 인식 영역 좌표 저장
- OCR 인식 결과 검수 화면 구현 (영역·신뢰도 시각화)
- 인식 오류 수정 및 원본값 보존, 동시 수정 충돌 제어
- 검수 확정 결과를 이후 분석에 반영 (낡은 분석 표시)
- 로컬 LLM(Ollama/Gemma) 연동 및 프롬프트 설계
- OCR 추출 데이터 요약 처리
- 문서 유형 자동 분류 (7종) 및 판단 근거 표시
- 액션아이템(실행 항목)·결정사항·일정 항목을 각각 구조화해 추출
- 액션아이템은 제목·설명·기한·담당 주체·원문 근거 등 실제 출력 정보만 저장
- 분석 결과 및 프롬프트 판 이력 관리
- 결과 출력 및 저장, 작업 로그 관리

**범위 경계** — 코드의 `features`는 액션아이템이 아니라 수행 과업·사업 범위를
`name`·`summary`로 추출하는 별도 분석이다. 문서 단위 액션아이템 추출은 유지하지만,
**AI가 새 태스크를 제안하는 기능과 그 승인·수정·거절·일괄 승인 기능은 범위에서
제외한다.** 최신 코드에 일부 경로가 남아 있어도 완료 기능으로 산정하지 않는다.

### ■ 문서 기반 금액 추출·집계 및 검증 기능 개발

- 금액 항목 구조화 추출 (항목명·원가구분·수량·단위·단가·금액·기간·원문 인용)
- 금액 전용 프롬프트와 명시적 금액 추출·재추출 동작
- 순수 JSON 검증 및 금액·수량 표준 숫자 변환
- 문서에 없는 값을 만들지 않도록 하는 원문 근거 제약
- 추출 결과를 검토 대기(`PENDING`) 상태로 저장
- **항목 합계와 문서 기재 합계 대조 및 불일치 표시**
- 금액 항목 승인·수정·거절·취소 화면 구현
- 승인·수정 승인된 항목만 프로젝트 집계와 산출물에 반영
- 재분석 검토 중에는 직전 검토 완료 금액 스냅샷 유지
- 프로젝트 단위 금액 집계 (합계·부가세·원가구분·집계 범위)
- 금액 판단 근거·계산식·출처 문서 연결 표시
- 문서 상세 화면에서 금액 추출·다시 추출
- 금액 탭·직접 경로 역할 제한 (`OWNER`·`EDITOR` 허용, `VIEWER` 차단)
- 금액 변경 후 금액 화면·대시보드·산출물 미리보기 갱신
- 집계 정확도 단위테스트 (같은 입력에 같은 결과)
- 금액 추출 정확도 측정 (정답 데이터 원문 대조)
- **[범위 제외] 금액 불일치 확인 태스크 제안 — AI 태스크 제안 제외 결정과 동일**

**이 영역의 원칙** — 있는 금액을 모으고 검증한다. **없는 금액을 만들지 않는다.**
계산과 집계는 코드가 하고 LLM 은 추출만 한다. 금액은 재계산으로 대조되므로
이 시스템에서 **정확도를 수치로 증명할 수 있는 영역**이다.

**최신 코드 대조 한계** — 주요 금액 화면과 API의 `VIEWER` 차단은 구현됐지만 단가
선례 API와 문서 상세 원시 분석 응답까지 완전히 차단되지는 않았다. 추출한 문서 기재
합계의 문서 컬럼 자동 반영, 값 수정·감소를 포함한 산출물 갱신 판정도 확인되지 않아
이 항목들은 부분 충족 또는 확인 필요로 남긴다.

### ■ RAG 기반 문서 검색 및 질의응답 개발

- 문서 임베딩 및 벡터 DB 적재
- 청킹 전략 수립 및 검색 품질 측정
- 의미 기반 문서 검색 기능 구현 (글자가 겹치지 않아도 찾는다)
- RAG 파이프라인(검색–증강–생성) 구현
- 검색 결과를 근거로 제시하는 응답 생성
- 업로드 문서 즉시 요약 기능
- 사용자 질의 기반 업로드 문서 검색·응답 기능
- 챗봇 인터페이스 구현
- 과거 유사 사업 단가 선례 검색 (비용 추정 근거 확보)
- 응답 출처 문서 표시 및 원문 이동

**우선순위** — 챗봇 인터페이스는 후순위로 둔다. **의미 검색과 선례 단가 검색을
먼저 만든다.** 그 둘은 금액 영역의 근거 확보에 직접 쓰이고, 챗봇은 그 위에
얹는 화면이다.

### ■ 프로젝트 산출물 자동 생성 기능 개발

- 산출물 종류 정의 (주간 보고서·결정사항 대장·회의 안건·프로젝트 현황)
- 대상 기간 및 출력 형식 선택 기능 (기본값을 두지 않는다)
- 생성 전 미리보기 (담길 내용 건수 표시, AI 호출 없이)
- 축적된 분석 결과를 재사용하는 생성 로직 (원문 재전송 없음)
- 파일 생성 (XLSX·HTML·MD·PDF)
- 산출물 이력 저장 및 재다운로드
- 이후 문서 추가 시 갱신 필요 표시
- 빈 산출물 생성 차단
- 손으로 만든 문서와 자동 생성물 대조 검증

**이 영역이 제품의 출력물이다.** 앞선 미니 프로젝트에서 팀이 손으로 만든
결정사항 대장과 주간 보고가 남아 있어, **같은 입력을 넣어 나란히 비교**할 수 있다.

**인수인계 문서 자동 생성은 범위에서 제외한다.** 프로젝트 현황과 기존 산출물에
내용이 겹치고 전용 데이터가 부족하기 때문이다. 주간 보고서·프로젝트 현황·결정사항
로그·회의 안건 및 산출물 이력은 그대로 유지한다.
