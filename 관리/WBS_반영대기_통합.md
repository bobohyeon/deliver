## 8. 추가 이슈 (8/4 저녁 ~ 8/5) — ISS-020 ~ ISS-033

### ISS-020 · 08-04 · 버그 · 해결 · 최재정 · 08-05

| 항목 | 내용 |
|---|---|
| 제목 | 자간이 넓은 PDF에서 텍스트가 분리되어 본문 검색 실패 |
| 현상 | `1. 제 안 자 :` 처럼 자간을 벌린 공문서에서 텍스트가 `제 / 안 / 자` 로 세로 분리되어 저장됨. **`제안자` 로 검색하면 0건** (`조경태` 는 붙어 있어 검색됨) |
| 원인 | 같은 줄 병합 로직이 OCR 경로(`ocr_extractor`)에만 적용되고 텍스트 레이어 경로(`pdf_extractor`)에는 없었음. 또한 텍스트 요소를 블록 단위로 만들면서 `x2`·`y2` 좌표를 채우지 않아 병합 판정에 쓸 수 없었음 |
| 조치 | 텍스트 요소를 **블록 단위에서 줄(line) 단위로 세분화**하고 `x2`·`y2` 좌표를 채운 뒤, `_merge_text_layer_elements()` 로 같은 줄을 병합. 이미 저장된 문서는 재업로드해야 반영됨 |

### ISS-026 · 08-04 · 성능 · 본프로젝트 이관 · 전원

| 항목 | 내용 |
|---|---|
| 제목 | 이미지가 포함된 12페이지 PDF 추출에 55초 소요 |
| 현상 | 업로드 후 응답까지 약 55초. 이미지 1장(ERD.png) 단독 업로드는 13초 |
| 원인 | **페이지 수가 아니라 OCR을 타는 이미지 개수에 비례.** `13초 × 이미지 3~4개 ≈ 55초` |
| 조치 | 가설 두 개를 측정으로 기각 — ① 확대 배율 상한(2.0) 적용 시 시간 변화 없음 ② PaddleOCR 보조 모델 3종 비활성화 시 오히려 16.7초. **OCR 추론 비용 자체가 원인**이므로 근본 개선은 본프로젝트로 이관. 미니프로젝트는 시연 시나리오로 대응(짧은 문서로 업로드 시연, 조회는 사전 업로드분 사용) |

### ISS-027 · 08-04 · 버그 · 해결 · 김보현 · 08-04

| 항목 | 내용 |
|---|---|
| 제목 | 전처리 도입 후 표 검출 좌표계 불일치로 표 병합 무력화 |
| 현상 | 예외는 발생하지 않으나 표 병합이 전혀 동작하지 않음 |
| 원인 | 표 셀 좌표는 전처리된 이미지(최대 2배 확대) 기준, OCR 요소 좌표는 원본 기준으로 되돌려져 있어 `cell.contains()` 가 매칭되지 않음. **두 기능이 서로 다른 브랜치에서 개발돼 자동 머지 시 좌표계 전제가 어긋남** |
| 조치 | 표 검출 입력을 전처리 전 원본 이미지로 변경해 좌표계를 통일. **자동 머지가 성공해도 좌표계·단위 같은 전제는 사람이 확인해야 한다** |

### ISS-031 · 08-05 · 환경 · 진행중 · 김보현

| 항목 | 내용 |
|---|---|
| 제목 | `docker-compose.yml` 이 `.env` 대신 `.env.example` 을 읽어 로컬 설정이 반영되지 않음 |
| 현상 | `backend/.env` 에 `API_KEY` 와 `USE_FAKE_AI=false` 를 넣어도 컨테이너에 전달되지 않아 **OpenAI 실연동이 불가** |
| 원인 | compose 의 `env_file` 이 `./backend/.env.example` 로 지정됨. 또한 `.dockerignore` 에 `.env` 가 있고 Dockerfile 이 `./app` 만 복사하므로 컨테이너 안에 `.env` 가 존재하지 않음 |
| 조치 | 개인 `docker-compose.override.yml` 로 `.env` 를 추가 로드(공유 파일 미수정). 정식 수정안은 `env_file` 에 `.env` 를 `required: false` 로 추가하는 것 — 하위 호환이므로 `.env` 가 없는 팀원에게 영향 없음. **팀 합의 후 반영 예정** |

### ISS-032 · 08-05 · 성능 · 진행중 · 전원

| 항목 | 내용 |

### 삭제 구현 시 정한 규칙

| 항목 | 결정 | 이유 |
|---|---|---|
| 삭제 순서 | **DB 먼저 커밋 → 파일 삭제** | 파일을 먼저 지우면 DB 삭제 실패 시 "기록은 있는데 파일이 없는" 상태가 되어 다운로드·재추출이 깨진다 |
| 파일 삭제 실패 | 경고 로그만 남기고 요청은 성공 처리 | 남은 파일은 조회·목록에 영향이 없다. 요청을 실패시키면 이미 지워진 DB 기록과 어긋난다 |
| 연관 데이터 | 모델 cascade 로 함께 삭제 | 추출 원문·분석 결과가 남으면 고아 데이터가 된다 |
| 확인 절차 | 화면에서 확인 창 승인 필수 | 되돌릴 수 없는 동작 |
| 상세 화면에서 삭제 시 | 목록으로 이동하며 **주소를 히스토리에서 대체** | 뒤로가기로 삭제된 문서에 접근하는 것을 막는다 |
