# 본프로젝트 아이디어 정리

지금까지 나온 아이디어를 한자리에 모으고, 각각 **왜 필요한지 · 무엇을 할 수 있는지 ·
무엇으로 증명할 것인지**를 붙인 문서다.

범위와 공수는 `관리/본프로젝트_범위결정_안건.md` 에서 다룬다. 이 문서는 그보다 앞단 —
**무엇을 만들 가치가 있는가**를 정리한다.

---

## 0. 전제 — 본프로젝트는 미니 프로젝트를 포함한다

새로 시작하지 않는다. 미니 프로젝트 결과물이 그대로 **기준선**이고, 본프로젝트는 그
위에 얹는다. 아이디어의 필요성을 논증할 때 **"기준선 대비 무엇이 늘어나는가"** 로
말해야 하므로, 이미 가진 것을 먼저 못박아 둔다.

| 이미 가진 것 | 내용 |
|---|---|
| 화면 | 6종 — `HOME` `LIST` `DTL` `UPL` `CMP` `NF` |
| API | 엔드포인트 6종 + 에러코드 11종 + `request_id` 로깅 |
| 데이터 | 3테이블 — `documents` 1:1 `extracted_texts` / 1:N `analyses` |
| 추출기 | PDF(PyMuPDF) · DOCX · HWPX · 이미지, `ExtractorRegistry` 로 확장자 매핑 |
| OCR 엔진 | 3종 — PaddleOCR · Tesseract · EasyOCR |
| 추출 방식 | 5종 — `TEXT_LAYER` `OCR` `DOCX` `HWPX` `HYBRID` |
| 하이브리드 | 텍스트 레이어는 살리고 이미지 영역만 OCR, 좌표를 PDF 기준으로 되돌려 정렬 |
| 분석기 | 2종 — 요약 · 분류, `analyzer_types` 로 선택 |
| 전처리 | 프리셋 4종 — `none` `light` `scan` `full` |
| 정확도 측정 | LabelMe JSON 정답 + CER |
| 테스트 | 단위 66행 · 통합 44항목 |
| 기록 | 이슈 46건 · 결정사항 29건 (미채택 대안과 이유까지) |

**이 목록이 아이디어 판단의 기준이다.** "없어서 만든다" 가 아니라 "있는 것을 어디까지
밀어붙이나" 가 본프로젝트의 성격이다.

기준선 수치도 함께 못박아 둔다. 개선을 주장할 때 비교 대상이 된다.

| 측정 항목 | 값 |
|---|---|
| PaddleOCR | 정확도 98.1% · 15,541ms |
| Tesseract | 정확도 64.4% · 931ms |
| EasyOCR | 정확도 81.8% · 15,496ms |
| 요약 | 3.2초 · 토큰 2,791 + 125 |
| 분류 | 1.6초 · 토큰 2,842 + 38 |
| 목록 조회 | `2+2N` — 문서 9건에 쿼리 20개 |

## 1. 아이디어를 판단하는 틀

미니 프로젝트 심사에서 1조가 **"주장에 기준·수치가 없다"** 로 지적받았다. 그래서
아이디어 단계부터 네 칸을 채운다. **네 번째 칸을 못 채우는 아이디어는 발표에서
주장으로 쓸 수 없다.**

| 칸 | 물어보는 것 |
|---|---|
| **왜 필요한가** | 지금 없어서 누가 무엇을 못 하는가 |
| **무엇을 할 수 있나** | 만들면 새로 가능해지는 행동은 무엇인가 |
| **기준선 대비 델타** | 0절의 어떤 값이 어떻게 바뀌는가 |
| **무엇으로 증명하나** | 발표에서 무엇을 보여주면 주장이 성립하는가 |

## 2. A군 — 우리가 만들다 남긴 것

미니 프로젝트에서 자산은 만들어 놓고 끝을 못 본 것들이다. **A군의 공통점은
"없는 것을 만드는" 게 아니라 "가진 것을 꺼내는" 일이라는 점**이다. 그래서 비용이 싸다.

### A-1. OCR 결과를 테이블에 저장

| | |
|---|---|
| 왜 필요한가 | 엔진 3종을 비교해 놓고 **결과를 버린다.** `/api/ocr-compare` 는 즉석 응답만 하고 저장 호출이 없다. 그래서 "지난주보다 나아졌나" 를 물으면 답할 수 없다 |
| 무엇을 할 수 있나 | 엔진별 정확도 **추이**를 본다. 전처리 프리셋을 바꿨을 때 좋아졌는지 나빠졌는지 판정한다. 문서 종류별로 어떤 엔진이 유리한지 통계를 낸다 |
| 기준선 대비 델타 | 측정값이 1회성 → **누적**. 3테이블 → 4테이블 |
| 무엇으로 증명하나 | 같은 문서를 프리셋만 바꿔 여러 번 돌린 뒤 **정확도 추이 표 한 장** |

**다른 아이디어의 전제다.** A-2 · A-3 · B-1 이 모두 이것 위에 선다. 순서상 가장 먼저다.

### A-2. `cer` 값 노출 + `WER` 추가

| | |
|---|---|
| 왜 필요한가 | CER 은 **이미 계산하고 있다.** 그런데 `1-CER` 을 정확도로 뒤집어 내보내 외부 논문·벤치마크 수치와 바로 못 맞춘다. 단어 단위(WER)는 아예 없다 |
| 무엇을 할 수 있나 | 우리 수치를 외부 공개 수치와 나란히 놓는다. 문자는 맞는데 단어 경계가 깨지는 경우(한국어 OCR 의 전형적 실패)를 구분해 낸다 |
| 기준선 대비 델타 | 지표 1종 → **3종**(`accuracy` · `cer` · `wer`) |
| 무엇으로 증명하나 | CER 은 낮은데 WER 은 높은 문서를 하나 찾아 **"왜 두 지표가 다 필요한가"** 를 한 장으로 |

주의할 점이 있다. 현재 CER 은 양쪽 문자열의 공백을 제거한 뒤 잰다. **공백 오류가
점수에 안 들어간다.** 밝히지 않으면 수치를 부풀린 것으로 보인다. 정규화 규칙을 화면과
문서에 같이 적는다.

### A-3. 3종 병렬 실행 후 자동 채택

| | |
|---|---|
| 왜 필요한가 | 지금은 3종을 **순차**로 돌리고(`compare()` 가 dict 리터럴에서 차례로 호출) 선택은 사람이 한다. 사용자에게 "엔진을 고르라" 는 것은 서비스가 판단을 미루는 것이다 |
| 무엇을 할 수 있나 | 사용자는 엔진을 몰라도 된다. 신뢰도 기준으로 자동 채택하고, 원하면 다른 엔진 결과를 펼쳐 본다 |
| 기준선 대비 델타 | 순차 약 31,968ms → **가장 느린 항목 수준**(이론상 15,541ms). 사용자 선택 → 자동 |
| 무엇으로 증명하나 | 같은 파일의 **순차 / 병렬 소요 시간 비교** + 자동 채택이 사람 선택과 일치한 비율 |

**단순 산술이며 실측이 아니다.** EasyOCR 은 별도 프로세스라 겹치기 쉽지만 Paddle 과
Tesseract 는 같은 프로세스라 GIL·메모리 경합을 받는다. 두 엔진 모두 무거운 연산을
C++ 에서 하므로 GIL 을 놓을 가능성이 높지만 **확인하지 않았다.** 8/17 에 스레드 2개로
재보고 채택을 결정한다.

### A-4. 텍스트 / 이미지 영역 시각화

| | |
|---|---|
| 왜 필요한가 | 하이브리드는 **우리가 3조보다 한 걸음 더 간 부분**인데(좌표를 PDF 기준으로 되돌려 정렬) 화면에는 `extract_method` 라는 글자 하나로만 나온다. 잘 만든 것이 안 보인다 |
| 무엇을 할 수 있나 | 어느 영역을 그대로 읽고 어느 영역을 OCR 했는지 페이지 위에 그린다. 추출이 틀렸을 때 **어디서 틀렸는지** 짚을 수 있다 |
| 기준선 대비 델타 | `extract_method` 값 1개 → **영역 단위 표시.** 새 데이터 없음 |
| 무엇으로 증명하나 | 텍스트와 이미지가 섞인 PDF 한 장의 **영역 표시 화면** |

**비용 대비 인상이 가장 큰 항목이다.** `LayoutElement` 에 `x` `y` `x2` `y2` 와
`source`("text"/"ocr") 가 이미 있다. 좌표를 새로 구할 필요가 없고 밖으로 내보내기만
하면 된다.

### A-5. 전처리 선택 + 비포 / 애프터

| | |
|---|---|
| 왜 필요한가 | 프리셋 4종이 있는데 **사용자가 고를 수 없다.** 전처리가 효과 있는지도 우리 스스로 화면으로 확인한 적이 없다 |
| 무엇을 할 수 있나 | 스캔 품질이 나쁜 문서에 `scan` · `full` 을 걸어 본다. 전처리 전후 이미지와 정확도를 나란히 본다 |
| 기준선 대비 델타 | 프리셋 4종이 내부 전용 → **선택 가능.** 효과가 수치로 남는다(A-1 과 결합) |
| 무엇으로 증명하나 | 기울어진 스캔 문서에 `full`(deskew 포함)을 걸어 **정확도 변화 한 줄** |

1조는 전처리를 설명했으나 **페이지 수와 처리 시간 기준이 없다는 지적**을 받았다.
우리는 A-1 저장이 있으니 기준을 붙일 수 있다. 같은 소재를 다르게 다루는 셈이다.

### A-6. LLM 재시도 · 폴백

| | |
|---|---|
| 왜 필요한가 | 타임아웃은 있으나(`AI_TIMEOUT_SECONDS` → 504) **한 번 실패하면 끝난다.** 재시도·대체 모델 코드가 없다. `FALLBACK_CATEGORY="기타"` 는 파싱 실패 시 기본 라벨이고 모델 폴백이 아니다 |
| 무엇을 할 수 있나 | 일시적 오류를 사용자에게 안 보인다. 상용 API 장애 때 하위 모델로 내려가 서비스를 이어간다 |
| 기준선 대비 델타 | 실패 시 504 → **재시도 후 성공률.** 시연 중 사고를 막는 안전장치 |
| 무엇으로 증명하나 | 실패를 일부러 주입해 **재시도 로그와 최종 성공**을 보여준다 |

### A-7. N+1 해소

| | |
|---|---|
| 왜 필요한가 | 문서 9건에 쿼리 20개다. 지금은 안 느리지만 **9건에서 20개면 900건에서는 1,802개**다 |
| 무엇을 할 수 있나 | 목록이 문서 수와 무관하게 일정한 쿼리로 열린다 |
| 기준선 대비 델타 | **쿼리 20 → 2** (목표치가 이미 정해져 있다) |
| 무엇으로 증명하나 | 동일 데이터에서 **쿼리 로그 개수 전후 비교** |

범위가 좁다. `DocumentListItem` 이 `analyses` 에서 쓰는 값은 `category` ·
`summary_preview` **두 개뿐**이라, `documents` 에 컬럼 2개만 붙이면 된다.

### A-8. 유저 / 개발자 화면 분리

| | |
|---|---|
| 왜 필요한가 | OCR 엔진 비교(`CMP`)가 사용자 경로 `/ocr-compare` 에 있다. **엔진 이름은 사용자에게 의미가 없다** |
| 무엇을 할 수 있나 | 사용자 화면은 업로드·조회로 단순해지고, 측정·비교는 개발자 영역으로 모인다 |
| 기준선 대비 델타 | 화면 6종이 **역할별로 갈라진다** |
| 무엇으로 증명하나 | 두 경로의 화면을 나란히 놓은 한 장 |

A-3(자동 채택)이 되면 자연스럽게 따라온다. 사용자가 고를 필요가 없어지므로 비교 화면이
사용자 경로에 있을 이유가 사라진다.

### A-9. 벡터DB + RAG

| | |
|---|---|
| 왜 필요한가 | 지금 검색은 **글자가 겹쳐야** 찾는다(`regexp_replace` + `ILIKE`). "휴가 규정" 으로 찾으면 "연차 사용" 문서를 못 찾는다 |
| 무엇을 할 수 있나 | 뜻으로 찾는다. 문서를 근거로 답하는 질의응답까지 열린다 |
| 기준선 대비 델타 | 글자 검색 → **의미 검색.** PostgreSQL 을 고른 이유를 실제로 쓴다 |
| 무엇으로 증명하나 | 글자가 하나도 안 겹치는 질의로 **찾아지는 것 / 안 찾아지는 것** 대조 |

**공수를 모른다.** 임베딩 모델 선정, 청킹 기준, 인덱스 운영이 다 미정이다.
모르는 것을 일정에 넣지 않는다는 원칙에 따라 후순위다.

## 3. B군 — 타팀에서 보고 가져올 만한 것

**B군은 A군과 성격이 다르다.** 우리 자산 위에 얹는 게 아니라 새로 시작하는 일이다.
그래서 "있으면 좋다" 만으로는 부족하고 **왜 우리 이야기에 필요한지**가 설명돼야 한다.

| ID | 아이디어 | 출처 | 왜 필요한가 / 무엇을 할 수 있나 | 판단 |
|---|---|---|---|---|
| B-1 | **사용자 피드백 수집** — 요약이 쓸만했는지 받기 | 1조 향후 | A-1 이 OCR 정확도를 정답으로 재는 것처럼, **LLM 품질은 정답이 없어 사람 평가밖에 없다.** 모으면 프롬프트 개선의 근거가 되고 `prompt_version` 별 비교가 가능해진다 | **A-1 과 짝이다.** 측정 이야기를 완성시킨다 |
| B-2 | 프롬프트 3갈래 — 교정 · 요약 · 번역 | 3조 | 분석기를 추가하는 일이라 **구조상 비용이 거의 없다**(`analyzer_types` 에 값 추가 + 분석기 클래스 1개). Q1 답변의 "갈아 끼울 수 있다" 를 실증하는 사례가 된다 | 낮은 비용. 발표 소재로 유용 |
| B-3 | 오탈자 교정 | 3조 | OCR 결과에 오탈자가 남는 것이 근본 문제다. 교정하면 **A-2 의 CER 이 실제로 좋아진다** — 지표와 기능이 연결된다 | B-2 로 구현. 효과를 수치로 볼 수 있다 |
| B-4 | 번역 | 3조 | 우리 문서는 한국어 위주다. **필요성이 약하다** | 후순위 |
| B-5 | PDF 다운로드 | 3조 | 미니 프로젝트에서 **의도적으로 제외**했다. 3조도 "지저분해서 추후 수정 예정" 이라 했다 | 제외 유지 |
| B-6 | 모델별 서버 포트 분리 | 1조 | 자체 모델을 여러 개 돌릴 때만 의미가 있다. 상용 API 를 쓰면 불필요 | D-12 에 종속 |
| B-7 | 자체 모델 병행 · 파인튜닝 | 1조 | 1조는 Gemma 1B 에서 **입력이 길어지면 출력이 영어로 쏠리는** 문제를 만나 재번역했다. 우리가 자체 모델을 쓰면 그대로 만난다. 재번역은 지연이 두 배가 되고 정보가 손실된다 | **권하지 않는다.** 다만 `analyses` 에 `model_name` · 토큰 · `latency_ms` 를 이미 쌓으니 **비교 실험 자체는 언제든 가능하다** |
| B-8 | Neon(관리형 PostgreSQL) · 클라우드 배포 | 3조 / 1조 | 시연 안정성은 오르지만 **기능이 늘지 않는다.** 로컬 도커로 이미 시연했다 | 후순위 |
| B-9 | 테스트 대상 파일명을 세세하게 기록 | 3조 | 재현성이 오른다. 지금은 유형으로만 적는다 | **비용 0.** 산출물 작성 규칙만 바꾸면 된다 |

## 4. C군 — 심사 피드백에서 나온 것

기능이 아니라 **일하는 방식**이다. 비용이 0 에 가깝고 발표 점수에 직결된다.

| ID | 할 것 | 근거 |
|---|---|---|
| C-1 | 용어를 **한 문장으로 먼저 정의**한다 | "추출기 · 분석기가 무슨 뜻인가" 를 질문받았다. 정의 없이 썼다 |
| C-2 | 데이터 구조는 **나눈 기준(값의 수명)** 부터 말한다 | 데이터 구조 재설명 요청을 받았다 |
| C-3 | 모든 주장에 **기준과 수치**를 붙인다 | 1조가 "기준 없음" 으로 지적받았다. 0절 표가 그 대비다 |
| C-4 | 안 한 것은 **"향후 개선사항"** 으로 배치한다 | "무조건 솔직한 게 좋은 것은 아니다" 는 지적. 우리는 이미 이 방식이었으니 유지 |
| C-5 | 산출물은 촘촘하게, **발표는 대표 사례 하나만** | 3조가 통합테스트 시나리오를 줄줄이 읽어 지적받았다 |

## 5. 아이디어를 세 갈래로 묶으면

낱개로 20개를 나열하면 발표에서 "한 장에 한 주장"(C-6)이 안 된다. 성격으로 묶으면
**세 갈래**가 되고, 각각이 발표 한 장의 주장이 된다.

| 갈래 | 주장 한 문장 | 묶이는 아이디어 |
|---|---|---|
| **측정된다** | 좋아졌다고 말하지 않고 **수치로 보여준다** | A-1 저장 · A-2 CER/WER · A-3 병렬·자동채택 · B-1 피드백 · B-3 교정 |
| **보인다** | 안에서 하던 일을 **밖으로 꺼낸다** | A-4 영역 시각화 · A-5 전처리 비포/애프터 · A-8 화면 분리 |
| **버틴다** | 실패해도 **서비스가 멈추지 않는다** | A-6 재시도·폴백 · A-7 N+1 · C-7 로그 누락 |

**세 갈래가 서로 맞물린다.** 저장(A-1)이 없으면 전처리 효과(A-5)를 수치로 말할 수
없고, 교정(B-3)을 넣어도 좋아졌는지 모른다. 시각화(A-4)가 없으면 추출이 틀린 위치를
못 짚는다. **A-1 이 뿌리다.**

미니 프로젝트가 "**되게 만들었다**" 였다면, 본프로젝트는 "**얼마나 잘 되는지 알고
있다**" 가 된다. 이 한 문장이 발표의 축이 될 수 있다.

## 6. 김보현 아이디어 — 작성 대기

**여기는 비워 둔다.** 팀장 본인이 따로 생각한 아이디어가 있으나 아직 문서에 없고,
추측으로 채우지 않는다.

채울 때는 2절 A군과 같은 네 칸으로 쓴다.

| 칸 | 물어볼 것 |
|---|---|
| 한 문장 정의 | 이것은 무엇인가. 기능 이름이 아니라 **하는 일**로 |
| 왜 필요한가 | 지금 없어서 **누가 무엇을 못 하는가.** 0절 기준선 중 무엇의 한계인가 |
| 무엇을 할 수 있나 | 만들면 **새로 가능해지는 행동**은 무엇인가 |
| 기준선 대비 델타 | 0절의 어떤 값이 어떻게 바뀌는가 |
| 무엇으로 증명하나 | 발표에서 무엇을 보여주면 주장이 성립하는가 |
| 5절 어디에 붙나 | 측정된다 / 보인다 / 버틴다 중 어디인가. 아니면 **네 번째 갈래**인가 |

**네 번째 갈래가 되는 아이디어라면 가치가 더 크다.** A·B·C군은 전부 기준선의 연장이라
"확장했다" 로 끝난다. 그 밖의 축이 하나 있으면 발표에서 **이 팀만의 것**이 된다.
