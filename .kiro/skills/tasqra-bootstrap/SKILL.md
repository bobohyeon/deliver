# Tasqra 세션 부트스트랩

새 대화방마다 사람이 맥락을 다시 설명하지 않게 한다. **먼저 스크립트를 돌리고,
그 출력만으로 부족한 부분만 파일을 읽는다.**

## 1. 스크립트를 돌린다

```bash
bash .kiro/skills/tasqra-bootstrap/scripts/bootstrap.sh
```

레포가 없으면 클론하고, 있으면 최신화한다. 그리고 한 번에 찍는다 —

- `deliver` 최근 커밋 · 현재 브랜치 · 커밋 안 된 변경
- `Tasqra` 최근 머지 PR · 열린 PR
- **기능명세서 xlsx ↔ md 어긋남 검사 결과**
- 임베딩 도구 목록

> 스크립트는 **읽기만 한다.** 커밋·푸시하지 않는다. 클론과 `fetch` 만 한다.

## 2. 출력을 읽고 이것만 판단한다

| 출력에 나온 것 | 해야 할 일 |
|---|---|
| `deliver` 에 커밋 안 된 변경이 있다 | 무엇인지 먼저 확인한다. 지우기 전에 커밋한다 |
| `Tasqra` 에 내가 모르는 머지 PR 이 있다 | 그 PR 이 내 담당 기능의 상태를 바꿨는지 본다 |
| 기능명세서가 **어긋난다** | **코드로 판정한다.** 문서끼리 비교해 정하지 않는다 |
| 어긋남 없음 | 명세서를 신뢰하고 진행한다 |

## 3. 문서는 필요한 것만 읽는다

전체를 읽지 않는다. 순서와 목적이 다르다.

| 파일 | 언제 |
|---|---|
| `관리/정정_이전대화방_인식오류.md` | **항상.** 짧고, 이전 방들이 틀린 것이 들어 있다 |
| `관리/인수인계.md` | 목차(`grep -n '^## '`)를 먼저 보고 **필요한 절만** |
| `관리/작업일지_*.md` | 최근 진행이 궁금할 때 **끝부분만** |
| `관리/기능명세서.md` | 특정 기능의 상태·의존관계가 필요할 때 `grep` 으로 |

`인수인계.md` 는 1,900줄이 넘는다. **통째로 읽지 않는다.**

## 4. 하지 말 것

- **`Tasqra` 에 커밋·푸시하지 않는다.** 변경 파일과 명령어를 정리해 사용자에게 준다
- **`deliver` 에 팀원 자료·조달 원본을 올리지 않는다.** public 레포다
- **모델이 필요한 측정을 시도하지 않는다.** 네트워크가 막혀 있어 실패한다.
  `run_eval.py` 는 사용자 PC 에서 돈다
- **측정을 반복하지 않는다.** 측정은 재정님·세현님 몫이다
