# Tasqra 프로젝트 지도 — 새 세션이 먼저 알아야 할 것

새 대화방마다 사람이 다시 설명하지 않게 하려고 둔 파일이다. **여기 적힌 것은
다시 묻지 않는다.** 여기 없는 것은 확인하고 말한다.

## 레포 두 개 — 권한이 다르다

| 레포 | 무엇 | 내가 커밋·푸시 |
|---|---|---|
| `bobohyeon/deliver` | 산출물 문서 · 작업일지 · 도구 | **해도 된다** (개인 레포) |
| `ParkSehyeon1009/Tasqra` | 제품 코드 | **절대 안 된다** (팀 레포) |

- `deliver` 작업 브랜치는 **`docs/design-artifacts-0805`** 다. `main` 에는 README 만 있다
- **`deliver` 는 public 이다.** 팀원이 준 자료·조달 원본 문서를 올리지 않는다
- Tasqra 는 코드를 내가 쓰고 **변경 파일과 명령어를 정리해 사용자가 직접** 커밋한다

사용자 PC 의 로컬 경로는 **서로 다른 상위 폴더**에 있다. 헷갈리면 `cd` 가 실패한다.

| 레포 | 로컬 경로 |
|---|---|
| `deliver` | `C:\dev\deliver` |
| `Tasqra` | `C:\dev\Tesqra\Tasqra` |

`C:\dev\Tesqra\deliver` 는 **없다.** 실제로 그렇게 안내해서 실패한 적이 있다.

## 커밋·푸시했으면 받는 명령어를 반드시 같이 준다

**내가 샌드박스에서 푸시한 것은 사용자 PC 에 자동으로 오지 않는다.** 사용자는
터미널로 git 을 쓰지만 이 방식이 처음이라 명령어를 모른다. 그래서 —

- 내가 `deliver` 에 푸시했으면 **끝에 `git pull` 명령어를 붙인다.** 예외 없다
- 사용자가 커밋·푸시해야 하면 **복사해 붙일 수 있는 형태**로 준다. 설명만 하지 않는다
- **PowerShell 기준**으로 쓴다. `&&` 대신 줄을 나누거나 `;` 를 쓴다
- PowerShell 은 `cd` 가 실패해도 다음 줄을 계속 실행한다. 그래서 디렉터리를 옮긴
  뒤 **`git branch --show-current` 같은 확인 명령을 넣어** 위치를 검증하게 한다
- 자세한 사용법은 `관리/git_명령어_모음.md` 에 있다. 사용자가 물으면 그걸 가리킨다

## 새 세션에서 읽는 순서

1. `관리/정정_이전대화방_인식오류.md` — 이전 방들이 틀렸던 것. **먼저 읽는다**
2. `관리/인수인계.md` — 목차를 보고 필요한 절만. `9-G` 가 90% 목표의 수학이다
3. `관리/작업일지_*.md` 끝부분 — 최근 진행

## 지금의 우선순위

**임베딩 검색 정확도 `R@1` 90%** (2026-08-19 회의). 문서 개수 제한은 두지 않기로
했다. 금액·대시보드는 그 이전 맥락이므로 먼저 꺼내지 않는다.

측정은 **재정님·세현님**이 한다. 내 몫은 계산·분석·코드이고 같은 측정을 반복하지
않는다.

## 반드시 피할 함정

**① 지표 정의를 확인하지 않고 숫자를 해석하는 것.** 같은 자료로 3.4배가 난다.

| | 뜻 |
|---|---|
| `accuracy@k` (= `Success@k` = `HitRate@k`) | 첫 정답의 순위가 `k` 이하면 1 |
| 표준 `recall@k` | 상위 `k` ∩ 정답 / 정답 전체 |

우리 도구는 앞의 것을 쓴다. **팀원 숫자와 나란히 놓기 전에 어느 정의인지 맞춘다.**

**② 일부만 보고 전체를 단정하는 것.** 이전 방들이 세 번 틀렸고 원인이 같았다 —
JSONL 첫 줄만 보고 / 파일 하나만 보고 / 표 한 칸만 보고. 숫자가 안 맞을 때
**문서가 틀렸다고 먼저 결론내지 않는다.** 다른 절을 먼저 읽는다.

**③ 기능 ID 만으로 말하는 것.** 사용자가 명세서를 매번 찾아볼 수 없다. 항상
작업명을 앞에 두고 ID 는 괄호에 넣는다 — "문서를 조각으로 자르기(`RAG-001-1`)".
**v5 에서 ID 가 2단 → 3단으로 바뀌었다** (`RAG-04` → `SRH-001`). 매핑표는
`관리/기능명세서.md` 뒷부분에 있다. 확인하지 않은 ID 를 쓰지 않는다.

## 기능명세서는 레포에 있다 — 복붙받지 않는다

| | 경로 |
|---|---|
| 원본(구글시트에서 내려받은 것) | `산출물/기능명세서_v5_세분화.xlsx` |
| 설계 근거판 | `관리/기능명세서.md` |

`openpyxl`·`pandas` 가 없어도 **`도구/xlsx_read.py`** 로 읽는다(표준 라이브러리만).
두 파일이 어긋났는지는 **`도구/spec_sync.py`** 가 검사한다.

**`.xlsm`(매크로 포함)도 그대로 읽힌다.** 같은 OOXML 컨테이너이고 시트 XML 구조가
동일하다 — 2026-08-20 에 실제 파일로 검증했고 추출 결과가 바이트까지 같았다.
`spec_sync.py` 는 `산출물/` 에서 `.xlsx`·`.xlsm` 을 자동으로 찾는다.
**`.xlsb`(바이너리 판)는 안 된다** — XML 이 아니다.

> **xlsx 는 사람이 손으로 갱신하므로 머지된 PR 을 못 따라간다.** 어긋남이 나오면
> 어느 쪽이 맞는지 **Tasqra 코드로 확인한다.** 문서끼리 비교해서 정하지 않는다.

## 샌드박스 제약 — 확인된 사실

- **외부 네트워크가 막혀 있다.** `pip install` 불가, 임베딩 모델 내려받기 불가,
  구글 스프레드시트 직접 읽기 불가. `git`·`gh` 는 된다
- 따라서 **모델이 필요한 측정(`run_eval.py`)은 사용자 PC 에서만** 된다.
  내가 여기서 돌릴 수 있는 것은 모델이 필요 없는 도구뿐이다
- `git ls-files` 는 한글 경로를 8진수로 감싼다. **`git -c core.quotepath=false`** 를 쓴다
- `/tmp` 는 bash 호출 사이에 남지 않는다. 생성과 사용을 같은 명령에 둔다
- **`python3` 는 3.9 다. 프로젝트는 3.11 이다**(`backend/Dockerfile` 이
  `python:3.11-slim`). 검사할 때 **`/root/.pyenv/versions/3.11.*/bin/python`** 을 쓴다.
  3.9 로 `py_compile` 하면 통과해도 프로젝트에서 다를 수 있다
- `node` 는 있지만 `NODE_OPTIONS` 프리로드가 깨져 있다. **`env -u NODE_OPTIONS node`** 로 쓴다
- `frontend/node_modules` 가 없어 `vite build`·`eslint` 를 돌릴 수 없다.
  대신 **`도구/check_jsx.py`** 로 import 경로·괄호·JSX 태그·CSS 균형을 검사한다.
  `--all` 로 기존 파일까지 돌려 **검사기 자체가 맞는지** 함께 확인한다
- `diff` 명령이 없다. 파일 비교는 파이썬으로 한다

## 팀 레포에서 테스트·개발 서버를 돌리는 방법 (확인된 사실)

- **테스트는 호스트에서 돈다.** `backend/Dockerfile` 이 `requirements.txt` 만 설치하고
  `./app`·`migrations` 만 복사한다 — 컨테이너에 `pytest` 도 `tests/` 도 없다
- 호스트 실행: `cd backend` → `python -m pytest tests/ -q`.
  **`pytest` 가 아니라 `python -m pytest`** 여야 한다(`pytest.ini`·`tests/__init__.py`
  가 없어 현재 폴더가 `sys.path` 에 들어가야 `app` 이 import 된다)
- `app.core.config` 는 **기본값 없는 설정이 13개**다. `backend/.env` 가 필요하다
  (`.env.example` 을 복사한다. `.gitignore` 153줄에 있어 커밋되지 않는다)
- **`docker-compose.yml` 에 `frontend` 서비스가 있다.** `npm run dev` 를 따로
  띄우지 않는다 — `./frontend:/app` 마운트 + Vite `--reload` 로 소스가 살아 있다.
  `http://localhost:5173`
- `api`·`worker` 도 `./backend/app:/app/app` 을 마운트한다. 코드 수정이 즉시 반영된다
- **실제 임베딩을 붙이려면** 호스트에서 `도구/embed_server.py`(포트 8900)를 띄우고
  `도구/docker-compose.override.yml` 을 Tasqra 에 복사한 뒤 **`docker compose up -d`**
  (`restart` 는 환경변수를 다시 읽지 않는다). 끝나면 override 파일을 지운다.
  **서버와 override 는 한 쌍이다** — 하나만 남기면 연결 거부가 난다
- 검색이 0건이면 먼저 **청크의 `embedding_model` 과 지금 쓰는 모델이 같은지** 본다.
  `WHERE embedding_model = 현재 모델` 로 걸리므로 다르면 조용히 0건이다

## 사용자 배경

자바·Spring 출신이다. 파이썬·FastAPI·SQLAlchemy 개념은 **Spring 대응물과 비교**해
설명한다. 코드 파일 머리에는 3단 주석을 유지한다 — ① 이 파일의 책임 ② 다른
파일과의 관계 ③ Spring 비교.

문서·발표자료는 **흑백 무채색**으로 만든다. 강조는 검정 하나로만 하고 색은 쓰지
않는다. 기준은 "다른 사람이 알아볼 수 있으면 충분하다" 다.
