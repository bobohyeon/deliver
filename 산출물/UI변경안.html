DocFlow UI 변경안

박세현님이 만든 목업 5화면을 기준으로, 분석기가 2개 이상이 될 때 달라져야 하는 부분만 표시한 문서다. 화면을 새로 만들지 않고 기존 화면에 얹는 것이 원칙이다. 기능 ID 는 관리/기능명세서.md 를 따른다.

검정 채움 = 바뀌거나 새로 생기는 부분 점선 = 새로 추가되는 영역 1번호 = 아래 표의 설명 번호
왜 새 화면을 만들지 않는가 — 액션아이템과 금액 항목은 구조가 같다. 문서에서 뽑음 → 확신도가 붙은 제안 카드 → 사람이 승인 → 태스크 등록 → 근거 역추적. 목업이 이미 그 틀을 만들어 놨으므로 제안 카드 · 승인 버튼 · 출처 링크 · AI 생성 배지를 그대로 재사용한다. 새로 만드는 것은 AnalyzerType 값 하나와 계산 함수뿐이다.

문서 유형 분포에 분석기 목록을 붙인 이유 미니 프로젝트 발표에서 "추출기·분석기가 무슨 뜻이냐" 를 질문받았다. 이 화면이 말 대신 답이 된다. 계약서에는 금액 분석기가 붙고 회의록에는 안 붙는다는 것을 한눈에 보여주면, 분석기가 갈아 끼울 수 있는 부품이라는 주장이 화면으로 증명된다.

7 4단계 "액션 아이템 추출" 을 "분석 N/M" 으로 일반화 목업은 특정 분석기 이름이 파이프라인 단계로 박혀 있다. 금액 분석기가 들어오면 단계가 6개, 다음 분석기에서 7개가 된다. 그때마다 화면과 상태 enum 을 고쳐야 한다. 분석기 목록 기반 진행률로 바꾸면 분석기를 늘려도 화면을 안 고친다 ANL-05

7번이 왜 가장 중요한가 분석기 라우팅(ANL-04)이 들어오면 문서마다 실행되는 분석기 수가 달라진다. 회의록은 3개, 계약서는 4개다. 단계 수가 고정된 화면으로는 표현할 수 없다. 이것 하나를 안 고치면 분석기를 추가할 때마다 세 사람이 각자 자기 코드를 고쳐야 한다.

13 합계 대조 영역 금액에만 있는 것이다. 액션아이템은 맞는지 알 수 없지만 금액은 합계를 재계산해 대조할 수 있다. 이게 금액 기능이 다른 분석기보다 신뢰도가 높은 이유다 AMT-03

그리고 이 카드가 태스크 보드를 살린다. 검증만 하면 문서가 깨끗할 때 태스크가 안 생겨 보드가 빈다. 단가 미확정은 거의 항상 발생하므로 승인 UI · 태스크 · 역추적이 전부 동작하는 화면을 만들 수 있다.

결론 — 목업의 UI 패턴을 하나도 새로 만들지 않는다. 제안 카드 · 승인 버튼 · 근거 링크 · AI 생성 배지 · 확신도 표시를 그대로 쓴다. 단 하나 구조를 바꿔야 하는 것은 파이프라인 단계다(변경 7). 분석기 이름이 단계로 박혀 있으면 분석기를 늘릴 때마다 세 사람이 각자 코드를 고쳐야 한다.

먼저 합의가 필요한 것

#안건왜 급한가
1 파이프라인 단계 일반화 (변경 7) 목업·프론트·상태 enum·백엔드가 다 걸린다. 나중에 고치면 네 곳을 고친다
2 분류 결과를 라우팅 기준으로 쓸지 (변경 10) documents.document_type 의 의미가 바뀐다. 마이그레이션 영향
3 단가 마스터를 데모 범위 자체 데이터로 고정할지 (변경 17) 금액 기능 전체의 전제. 안 정하면 계산이 성립하지 않는다
4 금액을 VIEWER 에게 보여줄지 조회 쿼리와 화면 분기에 영향

이 문서는 산출물/UI변경안.html 이다. 브라우저에서 열고 Ctrl+P → 대상을 PDF로 저장 으로 지정하면 인쇄본이 된다. 화면별로 페이지가 나뉜다.
