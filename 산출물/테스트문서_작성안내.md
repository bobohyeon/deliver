## 작성 원칙

- 실제 시험 전에는 `시험일자`, `Y/N`, `결함/이상 내용`을 비워 둔다.
- 시험 후 이상이 없으면 `Y`, 이상이 있으면 `N`과 결함 내용을 기록한다.
- 단위테스트는 화면에 보이는 행동과 결과를 순서대로 확인한다.
- 통합테스트는 정상·오류·경계조건이 저장소와 하위 처리까지 일관되게 이어지는지 확인한다.
- OCR 박스 병합을 원래 상태로 돌리는 기능은 **병합 되돌리기**라고 쓴다.

## 운영 확인 사항

- Alembic은 `backend` 작업 디렉터리 또는 컨테이너 `/app`에서 실행한다. 상대 경로가 달라지면 migrations를 찾지 못한다.
- 컨테이너가 code 137 뒤 재시작됐더라도 137만 원인으로 단정하지 않는다. 가장 마지막 traceback에서 최초 애플리케이션 예외를 확인한다.
- API 시작 smoke test로 서비스·스키마 import와 필수 Python 패키지 누락을 먼저 확인한다.
