## 로컬 LLM 기반 문서 분석·산출물 자동화 시스템 (Tasqra)

[업무 내용]

- 문서 검색 API 개발: FastAPI 로 의미 검색·키워드 검색·하이브리드 검색 3종을
  구현하고, 프로젝트 멤버십 범위를 쿼리 이전에 확정해 세 경로가 같은 권한 함수를
  재사용하도록 구성
- 하이브리드 검색 결합: 코사인 유사도와 트라이그램 유사도의 스케일이 달라 점수를
  더하지 않고 순위만 쓰는 RRF(`Σ 1/(k+rank)`)로 결합
- 벡터 검색 설계: PostgreSQL pgvector 1024차원 컬럼, HNSW 코사인 인덱스,
  pg_trgm GIN 인덱스를 SQLAlchemy·Alembic 으로 정의하고 임베딩 모델명을 검색
  조건에 포함해 서로 다른 벡터 공간이 섞이지 않게 처리
- 청킹·임베딩 파이프라인: OCR·추출 결과에서 제목과 반복 머리글·바닥글을 판정해
  구조 경계를 만들고, 페이지·표·본문 좌표를 보존한 청크 생성 → 임베딩 → 저장까지
  연결. 저장 전 벡터 개수와 차원을 검증하고 삭제·삽입을 한 트랜잭션으로 처리
- 재색인 처리: 본문 버전과 임베딩 모델이 같으면 재임베딩을 건너뛰고, OCR 검수
  확정으로 본문이 바뀌면 청크를 교체해 삭제된 내용이 검색되지 않도록 구성
- LLM 연동: 임베딩·AI 클라이언트를 Protocol 로 추상화하고 Fake 구현과
  OpenAI 호환 로컬 구현을 DI 로 교체 가능하게 구성. Ollama 로컬 모델 연동 시
  구조화 출력(`response_format: json_schema`)으로 응답 형식을 강제
- 문서 질의응답 개발: 검색 상위 청크 전문을 모델 컨텍스트 예산 안에서 조립하고,
  근거로 답할 수 없으면 `answerable=false` 로 확인 불가를 반환해 무근거 답변 차단.
  응답이 실제로 사용한 근거 번호만 남도록 검증
- 추출 결과 저장 흐름: 금액·결정사항·일정 추출 JSON 을 파싱·검증해 승인 대기
  상태로 저장하고, 승인된 항목만 산출물과 집계에 포함되도록 필터를 일치시킴
- 산출물 출력: 산출물 개요를 LLM 1회 호출로 채우고 XLSX(openpyxl) ·
  PDF(WeasyPrint) · HTML 보고서 형식으로 출력
- 비동기 처리: Celery + Redis 로 OCR·임베딩·LLM 호출을 워커로 분리해 오래 걸리는
  작업이 API 응답을 막지 않도록 구성
- 단위 테스트: 청킹, 문서 구조 판정, 키워드 검색, RRF 결합, 컨텍스트 조립,
  금액 추출·저장, 질의응답을 DB·모델 없이 검증
- 개발 환경: Docker Compose 로 API·워커·DB·프런트를 구성하고, pgvector 확장이
  필요해 DB 이미지를 `pgvector/pgvector:pg16` 으로 전환
- 검색 정확도 분석: 팀 실측값을 근거로 후보 수에 따른 상한, 리랭커가 받을 후보
  폭, 표본 크기와 지표 정의(`accuracy@k` 와 표준 `recall@k` 의 차이)를 계산해
  후속 실험 우선순위를 제안
  ※ 임베딩 모델 파인튜닝·리랭커 구현·정확도 반복 측정은 팀원 담당

## 숙소 예약 플랫폼 (Sloway)

[업무 내용]

- 예약·리뷰·검색·지도 기능 개발 및 형상관리 담당
- 예약 상태 전이 관리: 요청·확정·이용완료·취소 상태를 명시적으로 다루고,
  `ALREADY_CANCELLED` · `ALREADY_COMPLETED` 로 이미 끝난 요청의 중복 처리 차단
- 중복 예약·블랙아웃 차단: `countOverlappingRsvn()` 으로 날짜 구간 충돌을 확인하고
  호스트 예약 불가일은 `checkBlackOut()` 으로 분리해 검사
- 미결제 예약 자동 취소: 결제 대기 상태가 30분을 넘긴 예약을 조회해 취소 처리
- 권한 검증: `validateHostOwnership()` 로 호스트 소유권을, 본인 예약 여부는
  `.equals(memberNo)` 로 확인. 래퍼 타입을 참조 비교(`!=`)하면 같은 값도 다른
  객체로 판단될 수 있는 문제를 값 비교로 수정
- 리뷰 작성 자격 검증: 본인 예약, 이용 완료, 퇴실 후 14일 이내, 중복 리뷰 없음,
  별점 1~5 조건을 한 흐름으로 구성
- QueryDSL 동적 검색: 지역·가격·인원·날짜처럼 선택적인 조건을
  `BooleanExpression` 단위로 나눠 null 조건을 안전하게 조합
- DB 정합성 설계: 리뷰-예약 1:1, 답글-리뷰 1:1 을 UNIQUE 제약으로,
  도움돼요 중복을 `(user_no, review_no)` 복합 UNIQUE 로 막고 FK 인덱스 설정
  → 애플리케이션 검증과 DB 제약을 함께 두어 다른 저장 경로에서도 정합성 유지
- 형상관리: 브랜치·PR 기준 정리 및 병합 관리
  ※ AWS 배포 환경과 GitHub Actions 파이프라인은 팀원이 구축

## 카페 프랜차이즈 재무·매출 관리 (CoffePrince)

- 일별 매출 수정 기능(`editDaily()`)과 전표 재생성 연동
