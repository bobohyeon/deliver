## 무엇이 바뀌었나

두 가지를 넣었다.

| | 적용 | 자동인가 |
|---|---|---|
| 유니코드 정규화(NFC) | 모든 청킹 경로 | **자동** |
| 반복 노이즈 제거 | `mark_repeated_as_noise()` 를 부를 때만 | **직접 불러야 함** |

정규화는 자동이라 아무것도 안 해도 적용된다. 노이즈 제거는 오탐 위험이 있어서
기본으로 켜지 않았다 — 부르는 쪽이 목록을 확인하고 쓰게 했다.

## 1. 유니코드 정규화 — 왜 필요한가

한글은 같은 글자를 두 가지로 적을 수 있다. `가` 가 완성형 한 글자(NFC)일 수도
있고 `ㄱ+ㅏ` 두 글자(NFD)일 수도 있다. 눈으로는 같지만 바이트가 다르다.

**실측으로 확인한 결과다.**

| 입력 | `detect_heading` | 길이 |
|---|---|---|
| `제 3 장 계약 및 대금` (NFC) | `True` | 13 |
| 같은 문장 (NFD) | **`False`** | 24 |

정규식이 `제` 를 못 찾아서 **제목을 전부 놓친다.** 제목을 놓치면 두 가지가 깨진다.

- 청크가 제목에서 끊기지 않는다 (여러 절이 한 조각에 섞인다)
- 제목이 조각 맨 앞에 붙지 않는다 (BGE-M3 는 CLS 풀링이라 앞쪽 토큰이 주제 신호다)

그리고 토크나이저가 다르게 자르므로 **임베딩 자체가 달라진다.** 같은 문장인데
벡터가 다르면 검색이 안 된다.

### 좌표는 정규화하지 않는다

`content_start` · `content_end` 는 `extracted_texts.content` 안의 위치이고, DB 에
저장된 그 문자열은 정규화하지 않은 원본이다. 정규화한 길이로 좌표를 매기면
검색 결과에서 원문을 강조할 때 엉뚱한 구간을 잡는다 — NFD 면 길이가 두 배 가까이
차이난다.

그래서 **임베딩·판정에 쓰는 텍스트만 정규화하고 좌표는 원본 기준으로 둔다.**
검사로 확인했다. NFD 문서에서 `content[start:end]` 를 NFC 로 정규화하면 청크
텍스트와 정확히 일치한다(5/5).

대부분의 문서는 이미 NFC 라서 정규화가 아무것도 바꾸지 않는다. 그때는
`char_count` 와 `content_end - content_start` 가 같다.

## 2. 반복 노이즈 제거 — 조심해서 써야 한다

`mark_repeated_as_noise(groups)` 는 여러 묶음에 반복되는 줄을 `HEADER_FOOTER` 로
표시하고, 청킹이 그것을 버린다. `groups` 는 두 가지로 쓸 수 있다.

- **한 문서의 페이지들** → 페이지마다 반복되는 머리글·바닥글
- **여러 문서** → 문서마다 반복되는 상용구 (조달공고의 공통 법령 문구)

### 실제로 본문을 지웠다

처음에 `structure.py` 기본값으로 만들었더니 이렇게 됐다.

    숫자만 다른 문서 4건을 넣었을 때
      지운 것: '- # -'  '조달청 전자입찰 특별유의서에 따른다'
              '본문 # 입니다. 사업 기간은 십이 개월이다.'   <- 본문
              '제 # 장 개요'                              <- 제목
      결과: 청크 0개 (문서 전체가 사라졌다)

원인이 둘이다.

1. `normalize_repeated_text` 가 숫자를 `#` 로 바꾼다. 쪽번호(`- 3 -`, `- 4 -`)를
   같게 보려는 것인데, 그 때문에 `본문 1 입니다` 와 `본문 2 입니다` 도 같아진다.
2. 좌표가 없으면 상·하단 대역으로 걸러낼 수 없다.

### 그래서 기본값을 세 군데 바꿨다

| 설정 | `structure.py` 기본 | `mark_repeated_as_noise` 기본 |
|---|---|---|
| 숫자 치환 | 켬 | **끔** (`mask_digits=False`) |
| 반복 비율 | 0.5 (절반) | **0.9** (거의 전부) |
| 줄 길이 제한 | 없음 | **80자** |

실패했을 때 "아무것도 안 지움" 이 되도록 세게 잡았다. 덜 지우는 쪽이 안전하다.
같은 입력으로 다시 재니 상용구만 지워지고 본문·제목이 살아남았다.

### 제목은 후보에서 뺀다

조달공고는 서식이 같아서 `제 1 장 총칙` 같은 제목이 거의 모든 문서에 나온다.
그러면 반복으로 잡혀 전부 지워지는데, **제목은 노이즈가 아니라 구조다.** 청킹이
제목에서 조각을 끊고 제목을 조각 맨 앞에 붙이기 때문에, 제목이 지워지면 조각이
어느 절에 속했는지 알 수 없게 된다.

그래서 `element_type == "HEADING"` 인 줄은 후보에서 제외한다. 쪽번호·머리글은
`detect_heading` 이 제목으로 보지 않으므로(조항·번호 형식만 제목이다) 이 제외
때문에 놓치지 않는다.

### 쓰기 전에 반드시 목록을 볼 것

```python
for key, count, sample in repeated_noise_report(groups):
    print(f"{count}건  {sample!r}")
```

본문이 섞여 있으면 `min_ratio` 를 더 올리거나 `max_chars` 를 줄인다. 긴 상용구를
잡으려면 `max_chars=None` 으로 풀어야 하는데, 그때 본문이 함께 지워질 위험이
가장 크다.

## 3. 세현님 사용법 — 두 파일만 있으면 된다

`파일-06-preprocess/` 를 그대로 복사해서 쓰면 된다. **DB · SQLAlchemy · pydantic 이
필요 없다.** import 가 표준 라이브러리뿐이다(`re` · `unicodedata` · `dataclasses` ·
`collections` · `typing`).

```
app/
  __init__.py
  services/
    __init__.py
    chunking.py        <- 청킹 본체
  extractors/
    __init__.py
    structure.py       <- 제목·머리글 판정
```

```python
import sys
sys.path.insert(0, ".")   # 위 app/ 이 있는 폴더에서 실행

from app.services.chunking import (
    units_from_plain_text,      # 평문 -> 줄 단위
    mark_repeated_as_noise,     # 반복 줄을 노이즈로 표시 (선택)
    repeated_noise_report,      # 무엇이 지워질지 미리 보기
    chunk_units,                # 줄 -> 청크
    CharRatioTokenCounter,
    MAX_TOKENS, MIN_TOKENS, OVERLAP_TOKENS,
)

# 1) 문서마다 줄 단위로 쪼갠다. 정규화는 여기서 자동으로 된다.
groups = [units_from_plain_text(text) for text in documents]

# 2) 지울 목록을 먼저 눈으로 본다.
for key, count, sample in repeated_noise_report(groups):
    print(f"{count}건  {sample!r}")

# 3) 납득하면 표시한다. 건너뛰어도 된다(정규화는 이미 적용됨).
groups = mark_repeated_as_noise(groups)

# 4) 청크로 만든다. 세 값은 서비스와 같아야 한다.
counter = CharRatioTokenCounter()          # CHARS_PER_TOKEN = 1.89
for units in groups:
    chunks = chunk_units(
        units,
        counter=counter,
        max_tokens=MAX_TOKENS,             # 480
        min_tokens=MIN_TOKENS,             # 30
        overlap_tokens=OVERLAP_TOKENS,     # 48
    )
    for c in chunks:
        c.text        # 임베딩에 넣을 텍스트
        c.token_count # 추정 토큰 수
        c.heading     # 이 조각이 속한 제목
```

**세 값(`480` · `30` · `48`)을 바꾸지 말 것.** 서비스가 쓰는 값과 달라지면
평가 수치가 서비스 성능을 예측하지 못한다. 특히 `MIN_TOKENS` 는
`CHARS_PER_TOKEN` 과 곱해져 "몇 자 미만을 흡수하는가"로 동작하므로, 하나만
바꾸면 조각 경계가 조용히 달라진다.

## 4. 학습·평가 분할은 문서 단위로

청크당 질의 1개를 만들면 청크 단위로 나누기 쉬운데 **그러면 안 된다.**

`OVERLAP_TOKENS = 48` 이라 앞 청크의 끝 약 91자가 다음 청크 앞에 겹쳐 들어간다.
같은 문서의 인접 청크를 train/test 로 갈라 놓으면 **텍스트가 실제로 공유돼서**
성능이 과대평가된다.

**같은 문서의 청크는 전부 한쪽에만 들어가야 한다.**

## 5. 검사

`도구/check_chunking.py` 가 전처리까지 검사한다.

```
python3 도구/check_chunking.py <Tasqra/backend 경로>
```

검사 항목

- NFD 문서에서도 제목이 NFC 와 같게 나오는가
- NFD 에서 좌표가 원본 기준인가 (`content[start:end]` 를 NFC 하면 청크와 같은가)
- 반복 상용구를 잡는가
- **본문·제목을 잡지 않는가**
- 문서마다 반복되는 제목을 지우지 않는가
- 제목이 청크 맨 앞에 남는가
- 기본값이 보수적인가 (`min_ratio >= 0.8` · `max_chars` 가 있는가)
- 조각 경계가 옛 설정(1.2 · 48)과 같은가

**검사가 실질적인지 확인했다.** 정규화를 무력화하고 기본값을 느슨하게 되돌린
사본으로 돌려 보니 **8건이 실패**했다. NFD 제목이 3개에서 1개로 떨어지는 것까지
잡았다.

## 6. 아직 확인하지 못한 것

- **실제 코퍼스에서 노이즈 제거를 검증하지 못했다.** 세현님의 `g2b_qa.jsonl` 이
  이 환경에 없다. 기본값이 보수적이라 "덜 지우는" 쪽으로 실패하지만, 조달공고의
  긴 상용구는 `max_chars=80` 에 걸려 안 지워질 것이다. 목록을 보고 정해야 한다.
- **DB 의 기존 본문이 NFC 인지 확인하지 않았다.** NFC 면 정규화가 아무것도 바꾸지
  않으므로 재청킹이 필요 없다. 이 쿼리로 확인한다.

      SELECT document_id,
             content = normalize(content, NFC) AS is_nfc,
             length(content) AS len
      FROM extracted_texts ORDER BY document_id;

  `is_nfc` 가 전부 `t` 면 검색 품질 재측정이 필요 없다. `f` 가 있으면 그 문서는
  재청킹해야 하고 검색 결과가 달라질 수 있다.
- 노이즈 제거를 서비스 경로(`ocr_elements`)에 연결하지 않았다. 그쪽은 좌표가
  있어서 `detect_header_footer(use_position=True)` 를 쓰는 것이 정확하고,
  호출부가 문서 영역(`extraction_service`)이라 재정님 쪽이다.
