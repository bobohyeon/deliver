## 1. 먼저 — 대시보드 숫자가 이미 틀려 있었다

기존 `DashboardView` 는 문서 목록을 받아 **화면에서** 셌다.

```js
const processing = documents.filter(d => [...].includes(d.status))   // 이 .length 를 카드에 씀
```

그 `documents` 는 `GET /documents` 의 **첫 페이지**다.

| 지점 | 사실 |
|---|---|
| `document_router.py:18` | `size: int = Query(20, ge=1, le=100)` |
| `api/project.js` `listProjectDocuments` | 파라미터를 안 넘긴다 → `page=1, size=20` |
| `useWorkspaceData` | `documents: documentsQuery.data?.items ?? []` |

**문서가 21건을 넘는 프로젝트에서 카드 숫자가 조용히 틀린다.** 에러도 안 나고
화면도 정상으로 보인다. 지금 `[TEST]` 문서가 4건이라 드러나지 않았을 뿐이다.

페이지를 전부 받아 세는 방법은 문서가 늘수록 요청이 늘어 답이 아니다.
**세는 일은 DB 가 한다.** 그래서 이 작업의 요점은 카드를 추가하는 것이 아니라
**세는 위치를 화면에서 서버로 옮기는 것**이다.

## 4. 결정 세 개 — 읽을 때 걸릴 만한 것

### `open_tasks` 가 `0` 이 아니라 `null` 이다

`0` 을 주면 "열린 태스크가 0건" 과 "아직 셀 수 없다" 를 구별할 수 없다. 사용자가
**"할 일이 없다" 고 잘못 읽는다.** 화면은 `null` 이면 `—` 를 보여준다.

`decisions` ORM 모델이 생기면 `dashboard_service.get_overview` 에서 채우면 된다.
그때 `도구/check_dashboard.py` 의 "서비스가 open_tasks 를 채우지 않는다" 검사가
실패하는데, 그건 **의도된 신호**다(모델이 생겼으니 검사를 고칠 때가 됐다는 뜻).

### 필드 이름이 `pending_amount_items` 다

`pending_suggestions` 처럼 뭉뚱그리면 `decisions`·`schedule_items` 가 연결됐을 때
"이미 다 세고 있었다" 고 착각한다. **세는 대상을 이름에 박아 뒀다.**

### 유형 분포에서 NULL 을 버리지 않는다

`documents.document_type` 은 nullable 이고 분류 전 문서가 실제로 있다. 버리면
분포 합이 문서 수보다 작아져 **숫자를 믿을 수 없게 된다.** `document_type: null`
칸으로 오고 화면은 "미분류" 로 흐리게 표시한다 — 사람이 고른 `ETC`(기타)와
다르기 때문이다.

`--check` 는 **아무것도 쓰지 않고 적용 가능한지만 본다.** 통과하면 그다음 줄을

**주의** — `git switch -c <새브랜치> origin/main` 은 upstream 을 `origin/main` 으로
잡는다(`set up to track 'origin/main'` 이라고 나온다). 그래서 나중에 그냥
`git push` 를 치면 안 된다. 푸시할 때 upstream 을 바로잡는다.

```powershell
git push -u origin feat/dashboard-metrics
```

패치를 권하는 이유는 크기보다 **안전** 이다.

| | robocopy 로 파일 복사 | `git apply` |
|---|---|---|
| 팀원이 그 파일을 고쳤을 때 | **조용히 덮어쓴다** | **거부한다**(`error: patch does not apply`) |
| 옮기는 것 | 파일 11개 | 파일 1개 |
| 크기 | 73,570 바이트 | 51,740 바이트 |

공용 파일(`dependencies.py`·`main.py`)이 걱정이라면 이것이 그 걱정에 대한 실제
안전장치다. 복사는 경고 없이 남의 변경을 지운다.

`--check` 가 실패하면 그동안 main 이 움직였다는 뜻이다. 그때 알려주면 최신 기준으로
다시 만든다.

## 7. 아직 안 되는 것 (완료 판정 일부 미충족)

완료 판정이 "최신 데이터가 지표·목록에 반영되고 **각 항목에서** 관련 화면으로
이동할 수 있다" 인데, 두 곳이 이동하지 못한다.

| 항목 | 막힌 이유 |
|---|---|
| **문서 유형 분포 각 칸** | `DocumentsView` 에 유형 필터가 없다. `GET /documents` 는 `document_type` 파라미터를 받는데 **화면이 쓰지 않는다** |
| **금액 승인 대기** | 금액 화면 자체가 아직 없다 |

지금 이동시키면 걸러지지 않은 전체 목록이 떠서 "필터가 됐다" 고 잘못 읽히므로
**연결하지 않고 표시만 했다.** 누를 수 없는 카드는 `button` 이 아니라 `section`
으로 그려서 고장으로 보이지 않게 했다.

유형 분포 쪽은 서버가 이미 값을 주므로 `DocumentsView` 에 필터를 붙이는 일만
남았다. 그게 다음 순서다.

## 8. 남은 한계 하나

"OCR 확인 필요" 목록의 **항목**은 여전히 상위가 넘겨준 문서 목록(첫 20건)에서
고른다. 그 목록은 서버 집계에 넣지 않았다. 대신 **건수는 서버 값**을 쓰므로
"3건 표시 · 외 N건" 의 N 은 맞다. 문서가 21건을 넘고 검수 대상이 뒤쪽에만 있으면
미리보기가 비는데, 그때는 "검수가 필요한 문서가 N건 있습니다 · 최근 목록에는
없습니다" 로 사실에 맞게 표시한다.

막으려던 것을 막지 못하는 상태였다. 줄 단위 검사로 고쳐서 지금은 잡힌다.
